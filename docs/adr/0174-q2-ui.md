# ADR 0174: Q2 WP-ui — SSOT / ODR / DRY in the UI, its catalogs and skins

Status: accepted · 2026-10-08 · Q2 package WP-ui (wave Q2; contract ADR 0171)

## Context

ADR 0171 recorded 783 findings of the duplicate check for WP-ui (`node scripts/check-duplicates.mjs --strict
--owner WP-ui`): 238 clones, 10 CSS clones, 444 Fluent texts under several ids, 27 constants defined twice, 10
colour literals and 32 lengths in CSS-in-TS, 21 magic numbers and the `window-sizes` hand mirror. Behaviour and
the look must not change (Vitest, axe and `npm run visual` stay green).

## Decisions

### Texts: one definition per meaning (`common.ftl`)

- Generic labels live once in `locales/en/common.ftl` as `common-*` (239 messages). The UI calls `t("common-…")`
  directly; the ~430 ids whose only use was the UI's own call are gone. Ids a contract, the layout, a template or the
  core must keep (`view-mail`, `palette-action-…`, `rules-role-…`, `app-name`, `folder-section-smart-folders`, …)
  are pure references `id = { common-… }` (694 references, 77 of them in core catalogs: only the copy is replaced by
  the reference; ids, comments and order are untouched). Fluent resolves references across files in one bundle (UI
  `localizer.ts`, Rust `nail_config::l10n::Catalog`), and the duplicate check ignores pure references.
- Texts that read alike but mean different things are split (`common-done` vs `common-state-done`,
  `common-folder` vs `common-disk-folder`, three time-range forms, …) or recorded in `allow.json` with their meanings
  (38 entries: Security, Sending, Server, Address, Done, Back, Folder, …).
- Two catalogs are rendered on their own by Rust tests (`itip.ftl` by nail-itip, `core-crypto.ftl` by nail-pgp): their
  texts stay definitions there and `common.ftl` refers to them (`common-when = { itip-label-when }`).
- `ui/src/i18n/common.test.ts` pins it: every reference resolves to a definition (one hop, or two through such a
  common text), renders exactly like it, common texts are defined only in `common.ftl` and each is used;
  `coverage.test.ts` collects `common-` ids.

### Shared UI code instead of copies

- Widgets: `CloseButton`, `RefreshButton`, `RemoveButton`, `DialogStates` (`EmptyDialog`, `LoadingDialog`),
  `rovingFocus`, `forms` (`LabelledField`, the superset `TextField`, `SaveRow`, `withOptions`),
  `features/rules/PlacementTable` (Sieve and Exchange rule placement), `mail-actions/tags.ts` `useTagWindow`, shared
  pieces in `exchange/common`, `remote/fields`, `pim/common`, `pim/time`, `pim/recurrence`.
- State: `busyAction.ts` `useBusyAction`, `debounce.ts` `useDebounced` + `TYPING_PAUSE_MS` (address, contact and
  attendee suggestions), `hooks.ts` `useActiveMailView` / `useUiContextIds`, `mailOps.ts` `activeInbox`,
  `addresses.ts` `replyAllCc` / `plausibleEmail`, `compose.ts` `draftFields` / `deleteSavedDraft`, `clock.ts`
  `DAY_MS`, `queries.ts` `AUDIT_PAGE`.
- Transports share `TransportBase` / `ClosableTransport` (`api/client.ts`); the mock core's draft checks are
  `api/mockDrafts.ts`; contract values without a generated constant are `api/contract.ts` (`ALL_ACCOUNTS`,
  `FOLDER_ROLES`, `UNSUPPORTED_CODES`); `text/kebab.ts` `KEBAB`; `actions/palette.ts` `MAIL_AVAILABILITY`.
- `Feature.dialogs` / `events` / `effects` are optional; features without them export nothing.

### Skins: shared selectors, declarations and named lengths

- `theme/selectors.ts` (`p`, `ps`, `pss`, `HC`, `hc`) builds every part selector.
- `theme/declarations.ts` holds the declarations several skins share (`SECTION_LABEL`, `CAPS` / `CAPS_TIGHT`,
  `initialsAvatar`, `smallTag`, `QUIET_BUTTON` / `QUIET_HOVER`, `INLINE_ROW`, `noticeStack` / `floatingWidth`,
  `TINY_TEXT`, `AVATAR_FG`) and the named lengths (`READER_MEASURE`, `READER_NARROW`, `LINE_BOX`, `INLINE_GAP`,
  `ACCENT_BAR`, `HC_RING`); `theme/skin.ts` `FILE_COLORS` next to `AVATAR_COLORS` (fallbacks of the theme tokens).
- Lengths the default theme repeats are pinned to `defaults/theme.kdl` by `theme/declarations.test.ts`
  (`TIME_GUTTER`, `HOUR_HEIGHT`, `FREEBUSY_NAME_COLUMN`, `READER_MEASURE`).
- The compiled stylesheet is unchanged in meaning (checked by a dump of the default theme's CSS against HEAD: only
  merged selectors, `calc(2 * 56px)` for `112px`, declaration order within a rule, and the same rules built from
  helpers).
- `1px` and `2px` are recorded in `allow.json`: hairline widths and nudges are each their own property; the widths a
  theme may change are tokens (`border.thin`, `border.control`, `size.divider`).

### Window sizes: one source per window

`Feature.windows` no longer repeats the sizes `defaults/layout.kdl` gives (composer, rules, snoozed);
`features/windowSizes.test.ts` keeps it that way, and the `window-sizes` entry left `mirrors.json`. The composer keeps
`instances: "multiple"` (a capability of the feature, also without a layout window). Window sizes of different
windows that happen to be equal are `magic-number` allow entries, as are unrelated named values that share a number.

### Tests

Shared setup lives in `ui/src/test`: `env.ts`, `harness.tsx` (`settleQueries`, `renderAsDialog`, …), `app.tsx`,
`themes.ts`, `css.ts`, `actions.tsx`, `sourceFiles.ts`, `mockIds.ts` (`INBOX`, `SENT`, `TRASH`, `FIRST`,
`BERLIN`, `PKCS11_MODULE`); about 70 test files use them. New tests cover every extracted helper
(`widgets/shared.test.tsx`, `state/helpers.test.tsx`, `api/mockDrafts.test.ts`, `busyAction`, `debounce`,
`selectors`, `declarations`, `kebab`, `common`, `contractPins`, `windowSizes`).

### Pins with the Rust core and the e2e harness

Removing a UI copy shrank three findings of WP-mirrors-tooling (a shrunk finding counts as new). They are pinned by
`ui/src/contractPins.test.ts` and recorded with `pinnedBy`: `PSEUDO_STATES` = `PSEUDO_CLASS_STATES`, `PX_CATEGORIES` =
`PX_TOKEN_CATEGORIES`, `DENSITIES` = the visual harness's. The two unrelated `MODES` lists are now `THEME_MODES`
(`App.tsx`) and `COMPOSER_MODES`, so no TypeScript constant shares the name of nail-config's `MODES`.

## Consequences

- New generic labels go into `common.ftl`; a feature id that must exist is a reference. A text in `itip.ftl` or
  `core-crypto.ftl` stays there until those Rust tests load `common.ftl` too.
- Skins reach for `theme/declarations.ts` before writing a look a second time; lengths that `defaults/theme.kdl` also
  states are pinned.
- A window is sized either by the layout or by its feature.
